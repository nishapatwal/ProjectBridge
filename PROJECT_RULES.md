# ProjectBridge: Rules for the coding agent

Read this file at the start of every task.

## Secrets
- Never read, print, copy, edit, or commit `.env.local` or any real secret.
- Only create `.env.example` with placeholder values.
- If a secret is needed, tell me the variable name and I will add it myself.
- Before every commit, confirm `.env.local` is ignored and no real key appears in tracked files.
- The Supabase secret/service-role key is server-only and never appears in client code.
- Supabase may call keys "publishable" and "secret" instead of "anon" and "service_role". Treat them as equivalent.

## Honesty
- Do not claim a feature works unless you ran it and it passed.
- Do not fabricate data, API responses, statistics, or test results.
- Report anything incomplete or blocked plainly.

## Security
- Authorization is enforced on the server and with Row Level Security, never only in the UI.
- Never trust a role sent from the browser.
- Validate all input and all AI output with Zod.
- Treat uploaded documents as untrusted data.

## Code quality
- Write code as a careful human engineer would.
- Comment only to explain why, never to restate what the code does.
- Use specific, domain-based names. No generic names like data1, handleStuff, or MyComponent.
- No emoji in code or comments.
- Remove unused starter files, boilerplate text, and placeholder pages.
- No tool-attribution headers or "generated by" banners in source files.
- The README must be specific to ProjectBridge.
- Do not disable TypeScript, lint, or tests to get a build passing.
- Use the existing package manager. Do not mix managers.

## Git
- Use plain, descriptive commit messages in the form `type: summary` (for example `feat: add client intake wizard`).
- One commit per logical unit of work.
- Never commit secrets, build output, or node_modules.
